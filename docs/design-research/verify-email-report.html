Verify email without friction

A focused review of Champo’s six-digit email-verification step, adapted to its stadium visual language while preserving fast entry, recovery and accessibility.

Executive synthesis

Observed fact

Clear single job

The supplied screen has one dominant task: enter the six-digit code and continue. Email, resend state and expiry guidance are secondary.

Recommendation

Six cells, one value

Keep the branded segmented appearance, but support full-code paste, numeric keyboard, automatic advancement, Backspace recovery and platform OTP AutoFill.

Inference

Responsive composition

The tall reference translates well to phones. On iPad and desktop, a bounded card or split visual panel avoids an oversized, sparse form.

Recommendation

Recovery stays visible

Show the resend timer in place, expose a clear resend action when available, and keep “change email” reachable without competing with the primary action.

What leaders do differently

Source-reported claim

Apple and Google platform guidance prioritize OS assistance and a real editable text field over decorative custom keyboards.

Inference

For Champo, polish comes from the stadium shell and focus treatment; speed comes from system keyboard, paste and AutoFill. Neither should undermine the other.

Fast, low-friction first run

RecommendationAutofocus the first empty digit, allow the entire code to be pasted into any cell, announce field position to assistive technology, keep the destination email visible, and enable confirmation only when six digits exist. The only required decision is entering the code; resend and change-email remain optional recovery paths.

Risks and anti-patterns

Recommendation

Avoid split-field traps

Do not block paste, lose leading zeroes, reverse the number in RTL, or make Backspace navigation unpredictable.

Recommendation

Avoid timer pressure

The cooldown is not the code lifetime. Copy must not imply the code expires when resend becomes available.

Recommendation

Avoid visual-only state

Focus, error and success require accessible labels or live text, not gold borders alone.

Recommendations

High confidence · P0 · medium effort

Reliable entry model

Numeric inputs, LTR code order, paste distribution, one-time-code metadata and explicit verification.

High confidence · P0 · low effort

Responsive shell

Reuse Champo’s existing brand, stadium background and desktop split-panel breakpoint for continuity.

Medium confidence · P1 · low effort

Trust guidance

Briefly state that the code is single-use and time-limited without promising a duration not guaranteed by backend configuration.

Proposed experience

Information architecture: back + brand → trust emblem → instruction + masked destination → six-digit input → error/success region → confirm → resend cooldown/action → change email → legal links.

States: empty, entering, complete, verifying, invalid/expired, resend loading, resend success and missing-email fallback.

Accessibility: 48px+ touch targets, logical focus order, numeric keyboard, one-time-code metadata, readable focus/error contrast, reduced decorative accessibility noise, and no dependence on color.

Validation: test paste, leading zero, RTL order, screen reader labels, keyboard avoidance, invalid OTP recovery, cooldown completion and widths 390, 768 and 1440px.
